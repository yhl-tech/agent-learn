## 1. Agent 连续使用相同参数调用同一个工具时，运行器应该怎样判断和处理？

- **分类**：Agent Loop 与 Tool Calling
- **难度**：初中级
- **考察要点**：调用指纹、重复检测、停止条件、受控退出
- **参考答案**：
  - 运行器可以把工具名和规范化后的参数组成调用指纹，并在单次任务状态中记录最近的调用及结果。若环境和输入没有变化，却连续出现相同指纹，通常说明 Agent 没有利用上一次 Observation，可能已经陷入循环。
  - 不应第一次重复就直接判死循环，因为轮询状态、翻页或等待异步任务时可能需要重复调用。应结合工具类型、结果是否变化、连续重复次数和错误次数设置阈值，也可以检查 `A -> B -> A -> B` 这类短周期动作。
  - 达到阈值后不要继续消耗模型和工具资源。运行器应停止再次执行，复用已有结果或返回结构化的 `loop_detected` 状态，并根据场景让 Agent 改用其他动作、向用户补充提问或转人工。
  - 重复检测不能替代最大步数、超时和 Token 预算等硬限制。Trace 中还应记录触发的调用指纹、重复次数和停止原因；有副作用的工具更不能因为模型重复请求就再次直接执行。
- **通俗理解**：这像一个人拿着同一张取件码反复问同一个柜子，柜子状态又完全没变，继续询问通常不会得到新答案。系统可以先允许合理的重试，但连续多次没有进展时就应停下来，说明原因并换办法，而不是一直重复。
