## 1. 怎样避免 Agent 只在回答里声称“已经执行”，实际却没有调用工具？

- **分类**：Agent Loop 与工具执行
- **难度**：初中级
- **考察要点**：模型建议与真实执行、工具结果、完成条件、业务状态校验
- **参考答案**：
  - 模型输出“已发送”“已创建”或“已修改”只是文本，不能证明动作发生。真正的工具执行必须由应用运行时发起，并产生可关联的工具调用记录和结果。
  - 对需要真实操作的任务，完成条件不能只看最终回复，而应检查预期工具是否调用成功、`tool_call_id` 是否有对应结果，以及下游业务状态是否已经变更。
  - 工具失败、超时或没有返回成功证据时，Agent 应继续处理、明确失败或请求人工介入，不能把模型生成的成功描述直接展示为已完成。
- **通俗理解**：这像一个人说“邮件已经发了”，但发件箱里没有记录。系统要以真实的发送回执或业务状态为准，不能只相信一句听起来像完成了的话。

## 2. 工具返回为什么要区分“没有数据”和“调用失败”？返回结构应该包含什么？

- **分类**：工具接口与异常处理
- **难度**：初中级
- **考察要点**：统一返回契约、错误码、空结果、可重试性、模型后续决策
- **参考答案**：
  - “没有数据”表示工具正常执行但查询结果为空；“调用失败”表示参数、权限、网络或下游系统出了问题。两者混成空字符串或一段自然语言，模型可能把故障误判为业务上确实不存在数据。
  - 工具可返回稳定的结构，例如 `success`、`data`、`error_code`、`message`、`retryable` 和 `partial`。错误码至少应能区分参数错误、权限不足、超时、无数据和下游异常。
  - Agent 根据错误语义决定下一步：参数错误时澄清或修正，瞬时故障才有限重试，权限不足直接说明边界，正常空结果则按“未查询到数据”处理。
- **通俗理解**：商店说“没有这件商品”和“收银系统坏了”不是一回事。前者可以换商品，后者应修系统或稍后再试，若都只返回“没有”，后续处理就会走错方向。

## 3. 为什么对话摘要不能作为订单状态、审批结果等精确业务事实的唯一来源？

- **分类**：状态管理与 Memory
- **难度**：中级
- **考察要点**：有损摘要、事实漂移、结构化状态、来源与时效性
- **参考答案**：
  - 摘要是为了压缩上下文，会省略细节，也可能把否定、时间、金额或条件写错；多次滚动摘要后，误差还可能继续累积。
  - 订单状态、审批结果、权限和余额等精确事实应从数据库或业务工具重新读取，并保存在明确的结构化状态中。摘要只用于帮助模型理解对话背景，不能替代真实业务记录。
  - 需要长期保存的记忆应带来源、时间戳和版本；遇到冲突时优先使用最新的权威数据，并更新或废弃旧记忆，而不是让模型自行猜测。
- **通俗理解**：对话摘要像会议速记，适合回忆讨论过什么，却不能替代盖章后的合同和银行余额。涉及准确数字或当前状态时，应回到真实系统重新核对。
