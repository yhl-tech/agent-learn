## 1. Reflection Agent 是什么？为什么不能只让模型反复“再检查一遍”？

- **分类**：Agent Loop
- **难度**：初中级
- **考察要点**：生成-评估-修订闭环、验收标准、外部反馈、停止条件
- **参考答案**：
  - Reflection 会在初稿或执行结果之后增加评估环节，由同一个或另一个模型指出问题，再把反馈交给生成节点修订，形成“生成 -> 评估 -> 修订”的闭环。
  - 它适合代码、报告等有明确质量标准且迭代确实能改善结果的任务；简单问答或没有可判断标准的任务，增加反思只会提高延迟和成本。
  - 不能把模型的自我评价当成正确性证明。应优先使用测试结果、Schema 校验、工具返回或固定规则等外部证据，并锁定原始需求，避免模型把正确答案或验收标准改错。
  - 系统还应设置通过条件、最大修订轮数和失败出口；达到预算仍不通过时，应保留最佳版本并返回失败、追问用户或转人工。
- **通俗理解**：Reflection 像写完作业后按评分标准检查并订正，而不是不停对自己说“再认真想想”。如果没有标准答案、测试或老师反馈，检查次数越多也不代表越正确，反而可能把原来正确的内容改坏。
