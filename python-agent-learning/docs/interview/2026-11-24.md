## 1. 大模型 API 默认会记住上一轮对话吗？多轮 Agent 的上下文应该由谁维护？

- **分类**：Agent 状态管理与上下文
- **难度**：初级
- **考察要点**：无状态 API、消息历史、应用层状态、上下文预算
- **参考答案**：
  - 常见大模型 API 默认是无状态的，每次请求相互独立；模型只能看到本次请求中实际传入的 `messages`，不会因为使用同一个客户端或模型就自动记住上一轮。
  - 多轮上下文应由应用层按 `session_id` 保存和读取，并在下一次调用时按顺序重新传入必要的 system、user、assistant 消息。工具型 Agent 还要保留完整的工具调用与对应结果，不能只传用户问题和最终回答。
  - 历史不能无限追加。上下文接近窗口或预算上限时，应保留当前目标、关键约束和近期交互，并对较早内容做摘要、裁剪或按需检索；精确业务状态仍应从权威数据源重新读取。
  - 某些平台可能提供托管会话能力，但那是平台或应用层替开发者保存状态，不代表底层模型天然拥有长期记忆。
- **通俗理解**：模型像每次上班都会清空桌面的临时助手，只有本轮递给它的材料，它才看得到。聊天产品看起来“记得你”，其实是系统把必要的旧消息重新放回桌面；材料太多时还要整理重点，不能把所有历史一直堆上去。
