## 1. 工具返回的原始结果为什么不能既原样塞给模型，又直接流式展示给用户？

- **分类**：Tool Calling 与安全边界
- **难度**：初中级
- **考察要点**：结果最小化、模型上下文、用户输出、脱敏与结构化转换
- **参考答案**：
  - 工具原始结果是后端数据，不等于模型和用户都应该看到的内容。它可能包含无关字段、个人信息、内部路径、错误堆栈或密钥，原样传递既浪费上下文，也可能造成敏感信息泄漏。
  - 进入模型前应先按当前用户权限和任务目的做字段裁剪、数量限制、脱敏与 Schema 校验，只保留完成本轮决策需要的信息；工具返回的文本仍是不可信数据，不能让其中的指令改变系统规则。
  - 返回前端时还要生成单独的用户可见结果，只展示已授权的业务字段或摘要，并过滤内部错误、调试信息和敏感数据。不能因为某些字段可供后端或模型使用，就默认允许流式发送给浏览器。
  - 原始结果如确需用于审计，应放在受控存储中并设置访问权限和保留期限；Trace 可记录调用 ID、状态和脱敏摘要，避免把完整原始数据写进普通日志。
- **通俗理解**：工具原始结果像仓库里的整箱资料，办事员只应拿到完成任务需要的几页，用户看到的则是再次核对和脱敏后的结果。不能因为系统内部查到了手机号、路径或报错细节，就把整箱资料直接搬到聊天窗口里。
