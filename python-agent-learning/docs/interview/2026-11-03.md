## 1. 多用户共用一个 Agent 服务时，怎样避免会话状态和 Memory 串到别人？

- **分类**：状态与记忆
- **难度**：初中级
- **考察要点**：`thread_id`、用户身份、会话隔离、存储命名空间
- **参考答案**：
  - 短期状态应按会话标识隔离，例如 LangGraph Checkpointer 使用 `thread_id` 保存和恢复同一会话的状态；不同会话不能复用同一个 `thread_id`。
  - `thread_id` 表示一次会话，`user_id` 或 `tenant_id` 表示数据归属，两者不能混为一谈。一个用户可以有多个会话，共享会话也可能有多个参与者。
  - 这些标识必须由登录态和可信后端生成并校验归属，不能直接相信用户输入或让模型自行生成。
  - 长期记忆、检索条件和缓存键也要带用户或租户作用域，并用两个用户交叉访问同一接口的测试验证不会串话。
- **通俗理解**：`thread_id` 像每次聊天的房间号，`user_id` 像房间主人的身份。服务端既要把消息放进正确房间，也要检查来访者是否有权进入，不能只凭对方报出的房间号开门。

## 2. 为什么测试 Agent 时要使用 Fake LLM 和 Mock Tool，而不能只反复调用真实模型看答案？

- **分类**：Agent 测试
- **难度**：初中级
- **考察要点**：确定性测试、异常注入、工具轨迹、真实模型评测边界
- **参考答案**：
  - Fake LLM 可以按顺序返回预设的工具调用或最终答案，Mock Tool 可以固定返回成功、超时、权限失败等结果，使同一测试能够稳定复现。
  - 单元测试应优先断言可确定的行为，例如工具名称和参数、调用顺序、状态变化、重试次数、停止条件和 Schema，而不是要求最终自然语言逐字相同。
  - 测试集要覆盖正常调用、缺参、非法 JSON、工具异常、重复调用和超过最大步数等边界路径，并在 Prompt、模型或工具变更后运行回归测试。
  - Fake 和 Mock 只能验证运行时与流程逻辑，不能证明真实模型的泛化、语言质量和幻觉率；这些仍需真实模型评测、回放集和人工抽检。
- **通俗理解**：这像消防演练，测试人员可以主动制造“报警器故障”或“出口堵塞”，反复检查流程是否正确，而不用等待真实事故。演练能证明流程会不会乱，但不能完全代表真实现场，所以还要配合真实模型评测。
