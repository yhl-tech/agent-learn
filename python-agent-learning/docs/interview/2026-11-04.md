## 1. Function Calling 中的 `tool_choice` 有什么作用？`auto`、`required` 和 `none` 应该怎么选？

- **分类**：Tool Calling
- **难度**：初级
- **考察要点**：工具调用策略、自动选择、强制调用、禁用工具
- **参考答案**：
  - `tool_choice` 控制模型在当前轮是否可以或必须调用工具，它不负责执行工具。
  - `auto` 让模型自行决定直接回答还是调用零个、一个或多个工具，适合大多数普通 Agent 对话。
  - `required` 要求模型至少调用一个工具，适合答案必须来自实时查询或业务系统的场景；也可以强制指定某个工具。
  - `none` 禁止本轮调用工具，适合只允许文本回答的阶段。强制调用只能约束模型输出调用请求，程序侧仍要校验参数、权限和执行结果。
- **通俗理解**：`tool_choice` 像给办事员规定这一轮能不能去柜台查资料。`auto` 是自己判断，`required` 是必须查一次，`none` 是只能根据手头信息回答。

## 2. 流式返回 Function Call 时，为什么不能收到一段参数就立刻执行工具？

- **分类**：Tool Calling
- **难度**：初中级
- **考察要点**：增量事件、参数拼接、完整 JSON、多工具索引
- **参考答案**：
  - 流式响应中的工具参数通常被拆成多个增量片段，中间片段可能只是 `{"loc` 之类的不完整 JSON，直接解析或执行会报错，也可能使用到残缺参数。
  - 程序应按工具调用的 `index`、`item_id` 或 SDK 提供的标识分别累计参数，避免多个调用的片段混在一起。
  - 收到参数完成事件或内容块结束后，再解析完整 JSON，并继续做 Schema、业务和权限校验；若流被截断或最终 JSON 非法，应返回可处理的错误，不能执行工具。
  - 如果 SDK 已提供流式累加器，优先使用 SDK 能力；只有展示进度等需求才读取未完成片段，不能把它当成最终执行参数。
- **通俗理解**：流式参数像一张被分成多条短信发送的地址，前几条可能只有“北京市朝”。必须等地址收完整并核对格式后再寄件，否则很容易寄错地方。

## 3. 模型返回工具名后，为什么要通过工具注册表查找，而不能直接执行任意同名函数？

- **分类**：工具执行
- **难度**：初中级
- **考察要点**：工具白名单、名称映射、未知工具、执行边界
- **参考答案**：
  - 模型返回的工具名只是字符串，而且可能生成不存在或不应暴露的名称。程序应只在预先注册的工具表中查找，不能通过 `eval`、任意反射或动态导入直接执行。
  - 工具注册表负责把公开给模型的名称映射到明确的函数对象，同时便于统一增加参数校验、权限、超时和审计逻辑。
  - 找不到工具时应返回结构化的“未知工具”错误，让 Agent 改选工具或结束，而不是猜测名称或执行相近函数。
  - 注册表只能限制“可以调用什么”，真正执行前仍要校验参数和当前用户权限，尤其不能因为工具在白名单中就默认所有用户都有权调用。
- **通俗理解**：模型报出的工具名像访客说出的房间名，前台只能按登记表带他去允许进入的房间。登记表里没有就拒绝并说明原因，不能让访客自己在楼里找门打开。
