## 1. 设计 Agent 的会话表和消息表时，为什么不能只保存一段拼接后的聊天文本？

- **分类**：Agent 状态管理与工程落地
- **难度**：初中级
- **考察要点**：会话归属、消息顺序、角色类型、工具调用关联、恢复执行
- **参考答案**：
  - 拼接后的文本会丢失消息边界、角色、先后顺序和工具调用关系，程序只能重新猜哪些内容来自用户、模型或工具，难以可靠地恢复多轮上下文和排查问题。
  - 会话记录至少应包含 `session_id`、用户或租户归属、状态、创建与更新时间；一次会话中可以有多轮运行，必要时再关联 `run_id` 或 Checkpoint，而不能把会话 ID、请求 ID 和运行 ID 混为一谈。
  - 消息记录至少应包含稳定的 `message_id`、`session_id`、顺序号、角色或事件类型、结构化内容和时间。工具调用还要保存 `tool_call_id`、工具名、参数及对应结果的关联，保证恢复时仍能成对重放。
  - 写入应具备原子性和幂等性，避免流式重连或请求重试产生重复消息。大文件和完整工具原始结果可外置存储并只保留引用；敏感内容还要按权限、脱敏和保留期限处理。
- **通俗理解**：只存一整段聊天文本，像把会议里所有人的发言去掉姓名和时间后粘成一段，之后很难知道谁说了什么、哪次提问对应哪次回答。把会话、消息顺序和工具调用编号分别记清楚，系统才能在重启或中断后接着处理，也更容易查错。
