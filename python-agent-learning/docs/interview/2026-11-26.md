## 1. 多轮 RAG 中，用户只问“它支持退款吗”时，为什么不能直接拿这句话或整段聊天记录去检索？

- **分类**：RAG 多轮问答
- **难度**：初中级
- **考察要点**：指代消解、独立查询、对话历史、检索与生成分工
- **参考答案**：
  - “它支持退款吗”包含指代和省略，单独交给 Retriever 时缺少明确实体，容易召回无关内容；把整段聊天记录直接做 Embedding 或关键词检索，又会混入旧问题、模型回答和无关话题，污染查询。
  - 应先结合必要的对话历史判断本轮是否延续上文。若是，就把追问改写成可脱离历史理解的独立查询，例如“某产品是否支持退款”；若用户已经切换到新话题，则保留原问题，不要强行拼接旧实体。
  - Retriever 只接收改写后的干净查询；生成答案时仍应保留用户原始问题，并结合召回文档和必要的会话上下文作答。改写只用于找资料，不能擅自改变时间、产品型号、否定条件等关键约束。
  - 应用测试应覆盖明确追问、模糊指代、新话题切换和改写错误等样例，并比较改写前后的正确文档命中率，不能只凭改写后的句子看起来更完整就判断有效。
- **通俗理解**：用户先问“介绍一下 A 产品”，接着说“它能退款吗”，检索系统若只看到“它”就不知道在找谁；但把整段聊天原样当搜索词，又像拿整页聊天截图去查字典。更合适的做法是先整理成“A 产品是否支持退款”再检索，同时保留用户原话用于最后回答。
