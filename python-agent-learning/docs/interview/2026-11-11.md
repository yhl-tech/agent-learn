## 1. 模型的上下文窗口已经很大，为什么还需要 RAG？什么时候可以直接使用长上下文？

- **分类**：RAG 基础选型
- **难度**：初中级
- **考察要点**：长上下文、检索范围、知识更新、权限过滤、成本与延迟
- **参考答案**：
  - 长上下文解决的是“一次请求能放入多少内容”，RAG 解决的是“从大量外部数据中选出哪些内容再交给模型”。窗口变大不会自动完成资料筛选、权限过滤、版本更新和来源定位。
  - 当材料数量少、内容稳定、能够完整放入窗口，并且任务需要通读全文或跨章节总结时，可以直接使用长上下文，避免检索漏掉关键片段。
  - 当知识库很大、经常变化、不同用户权限不同，或只需回答局部事实问题时，更适合先用 RAG 检索相关证据。这样可以减少无关输入，并让成本、首字延迟和引用来源更可控。
  - 两者不是互斥关系。实际项目可以先用检索缩小范围，再把命中的多段材料放入较长上下文中综合回答；最终应使用真实问题集比较正确率、成本和延迟后选型。
- **通俗理解**：长上下文像一张更大的书桌，能摊开更多资料，但不会自动帮你从整个档案馆里找出该看的几页。资料少且需要通读时直接放上桌即可；资料很多、常更新或有权限限制时，应先用 RAG 找准材料，再交给模型阅读。
