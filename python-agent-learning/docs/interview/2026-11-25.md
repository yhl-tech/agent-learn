## 1. 同一会话同时收到两条用户消息时，为什么不能直接并发运行两个 Agent Loop？

- **分类**：Agent 状态管理与工程落地
- **难度**：初中级
- **考察要点**：会话级串行、消息顺序、状态覆盖、重复请求、并发策略
- **参考答案**：
  - 两个 Loop 若同时读取同一份旧状态并写回，可能互相覆盖消息、Checkpoint 或工具结果；后完成的请求不一定是后发的请求，最终对话顺序和 Agent 判断会变得不一致。
  - 通常应以 `session_id` 或 `thread_id` 为粒度控制并发：同一会话同一时刻只保留一个活跃 Run，后续请求根据产品交互选择排队、拒绝，或先中断旧 Run 再开始新 Run；不同会话仍可并行。
  - 每次执行还应有独立的 `run_id` 和明确状态，写入消息时保存顺序号或版本。客户端超时重试要带稳定的请求 ID，避免同一条消息被创建和执行两次。
  - 不能只在前端禁用发送按钮，因为多标签页、网络重试或多个服务实例仍可能同时请求；最终约束应由服务端会话状态或框架的并发策略保证。
- **通俗理解**：这像两个人同时在同一本账本的同一页记账，都先看到旧余额，最后一个写入的人可能把另一个人的记录盖掉。更稳妥的方式是同一本账一次只让一个人写，后来的先排队或明确取消前一笔；不同账本则可以同时处理。
