## 1. 多轮对话中，怎样判断用户是在继续当前任务、纠正旧信息，还是开启新任务？

- **分类**：Agent 状态管理
- **难度**：初中级
- **考察要点**：任务边界、结构化状态、补充与纠错、会话和任务标识
- **参考答案**：
  - 不能只看两条消息的时间间隔，也不能让模型每轮只凭完整聊天记录重新猜。系统应维护当前任务的目标、待补信息、已确认条件、已完成步骤和状态，并结合这些字段判断新输入与当前任务的关系。
  - 如果新输入补齐当前待确认字段，就继续原任务；如果它否定或修改已确认条件，就更新对应字段，并让依赖旧值的未执行步骤失效；如果用户明确切换目标，则创建新的 `task_id`，按产品规则暂停或结束旧任务。
  - `session_id` 或 `thread_id` 表示一段连续会话，`task_id` 表示会话中的具体任务，一次会话可以包含多个任务。判断置信度不足时应追问，而不是擅自覆盖当前目标。
  - 可以用“补充、纠错、澄清回复、新任务、取消”五类样例测试路由结果，并检查旧任务状态没有被新任务污染。
- **通俗理解**：同一个聊天窗口像一张办公桌，桌上可以先处理退款，再临时查天气，但这并不代表两件事是同一个任务。系统要看用户是在补材料、改条件还是换了一件事；拿不准时先问清楚，不能把新话题直接写进旧任务。
