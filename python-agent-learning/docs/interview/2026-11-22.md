## 1. 为什么 Agent 的查询工具和写入工具不能使用同一套执行规则？

- **分类**：Tool Calling 与基础安全边界
- **难度**：初中级
- **考察要点**：副作用分级、后端鉴权、执行前确认、幂等与审计
- **参考答案**：
  - 查询工具通常只读取数据，重复调用主要带来隐私、越权或资源消耗风险；发消息、下单、改配置、删文件等写入工具会改变真实业务状态，误调用或重复调用可能直接造成损失。
  - 工具注册时应标明只读、可逆写入或高风险写入，并只向当前任务暴露必要工具。模型可以提出调用，但用户身份、对象权限、参数和当前业务状态必须由后端使用可信数据重新校验。
  - 对有副作用的操作，应先展示目标和关键参数；高风险操作需要用户确认或审批。确认必须绑定这一次具体动作，参数发生变化后不能继续沿用旧确认。
  - 正式执行还要使用稳定的幂等键，避免重试产生重复写入，并记录发起人、工具、参数摘要、审批和执行结果。这样即使模型选错工具，程序边界也能拦截或追溯。
- **通俗理解**：查快递和取消订单不能共用一个“直接执行”按钮，因为前者多查一次通常没改变结果，后者多执行一次可能造成真实损失。就像查看账单可以直接看，转账则要核对收款人、金额并确认，系统还要防止重复扣款。
