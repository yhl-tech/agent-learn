## 1. Agent Loop 收到模型响应后，为什么不能只判断 `content` 是否为空？

- **分类**：Agent Loop 与 Tool Calling
- **难度**：初中级
- **考察要点**：结束原因、工具调用分支、输出截断、流式响应
- **参考答案**：
  - `content` 为空不一定表示失败：模型可能返回了工具调用；`content` 非空也不一定表示答案完整，生成可能因 Token 上限而被截断。应用应优先读取 `finish_reason` 或 `stop_reason`，再决定下一步。
  - 结束原因为工具调用时，解析并校验完整的工具参数，执行工具并把结果回填后继续循环；正常结束时才把文本当作最终答案。
  - 结束原因为 `length`、`max_tokens` 或上下文超限时，不能执行可能被截断的工具参数，也不能把残缺文本冒充完整答案，应调整 Token 预算、缩短上下文或明确报错后重试。
  - 流式响应中的结束原因通常只在尾部事件出现，工具参数也可能分多段返回，因此必须先按调用索引拼接完整内容，再根据最终结束原因处理。不同模型厂商的枚举名称不同，接入层应统一映射，并对未知值采用安全失败。
- **通俗理解**：模型响应像电话结束提示，“正常说完”“要去查资料”和“话费不足被掐断”看起来都可能暂时没有正文，但后续处理完全不同。程序要先看结束原因，再决定回答用户、调用工具还是报错重试，不能只看有没有文字。
